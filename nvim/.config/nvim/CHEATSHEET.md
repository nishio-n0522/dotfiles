# Neovim チートシート（本リポジトリ devcontainer 環境用）

LazyVim 16 ベースの `.devcontainer/nvim/` 設定に対応。**リーダーキーは `Space`**。
`Space` を押して一拍待つと which-key が次に押せるキーの一覧を表示するので、迷ったらまず `Space`。

## 起動と終了

| 操作 | コマンド / キー |
| --- | --- |
| 起動 | `nvim` / `nvim <ファイル>`（コンテナ内シェルで） |
| 保存 | `:w` または `Ctrl+s`（insert モード中でも可） |
| 保存して終了 | `:x`（または `ZZ`） |
| 保存せず終了 | `:q!`（または `ZQ`） |
| 全ウィンドウ終了 | `Space q q`（未保存があれば保存するか聞かれる。黙って消えることはない） |

## モード（最重要概念）

VS Code と違い、Neovim は「モード」で入力の意味が変わる。

| モード | 入り方 | 用途 |
| --- | --- | --- |
| Normal | `Esc` | 移動・編集コマンド（ホームポジション） |
| Insert | `i`（カーソル前）/ `a`（後）/ `o`（下に新行） | 文字入力 |
| Visual | `v`（文字）/ `V`(行) / `Ctrl+v`（矩形） | 範囲選択 |
| Command | `:` | ex コマンド実行 |

**困ったら `Esc` 連打で Normal モードに戻る。** 日本語入力(IME)は Normal モードでは必ず OFF に。
ステータスラインに `recording @q` と出たら誤って `q`（マクロ記録開始）を押している。もう一度 `q` で解除。
**マクロ記録中は which-key のメニュー（`Space` や `g` のポップアップ）が出なくなる**のもこのサイン。
`Space` でメニューが出ずカーソルが動くだけのときは、Normal モード以外にいる（Insert /
Terminal。ステータスライン左端で確認）か、起動直後でプラグインのロード前に押している。
`Esc`（ターミナルは `F2`）で Normal に戻り、一拍おいて押し直せば出る。

## 移動（Normal モード）

| キー | 動き |
| --- | --- |
| `h j k l` | ← ↓ ↑ →（矢印キーも使える） |
| `w` / `b` | 次の単語 / 前の単語 |
| `0` / `$` | 行頭 / 行末 |
| `gg` / `G` | ファイル先頭 / 末尾 |
| `{数字}G` | 指定行へ（例 `42G`） |
| `Ctrl+d` / `Ctrl+u` | 半ページ下 / 上 |
| `Ctrl+e` / `Ctrl+y` | カーソルは動かさず表示だけ1行下 / 上へスクロール（マウスホイール相当） |
| `zz` / `zt` / `zb` | カーソル行を画面の中央 / 上端 / 下端へ（表示位置の整え） |
| `f{文字}` / `F{文字}` | 行内で右 / 左方向にその文字の上へジャンプ |
| `t{文字}` / `T{文字}` | 同上、ただし文字の手前 / 直後に止まる（`dt)` `ct,` など編集との組み合わせで活躍） |
| `;` / `,` | 直前の f / t / F / T を同方向 / 逆方向にリピート |
| `%` | 対応する括弧へ |
| `Ctrl+o` / `Ctrl+i` | ジャンプ履歴を戻る / 進む（gd の後に多用） |

f / t / F / T を押すと**画面が減光して1文字の入力待ち**になる（flash.nvim の演出。故障ではない）。
対象の文字を打つと候補位置がハイライトされる。やめるときは `Esc`。

## 編集の基本（Normal モード）

| キー | 操作 |
| --- | --- |
| `u` / `Ctrl+r` | Undo / Redo |
| `dd` / `yy` | 行を削除（切り取り）/ コピー（ヤンク） |
| `p` / `P` | カーソル後 / 前に貼り付け |
| `x` | 1文字削除 |
| `ciw` | カーソル位置の単語を消して入力開始（**c**hange **i**nner **w**ord） |
| `ci"` / `ci(` | `"..."` / `(...)` の中身を消して入力開始 |
| `.` | 直前の編集を繰り返す |
| `Alt+j` / `Alt+k` | 行を下 / 上に移動（VS Code の Alt+↓/↑ 相当。`V` で複数行選択してからも可） |
| `V` で行選択 → `d` | 選択した行をまとめて削除（切り取り）。VS Code の Ctrl+Shift+K 相当 |
| `>` / `<`（Visual 選択後） | インデント / アンインデント |
| `gcc` | 行コメント切り替え（選択して `gc` も可） |

パターン: `d`(削除) `y`(コピー) `c`(変更) + 範囲(`iw` 単語, `i"` 引用符内, `ap` 段落…)の組み合わせで覚える。

## ファイル内検索・置換

| 操作 | キー |
| --- | --- |
| 検索 | `/文字列` → `Enter`、`n` / `N` で次 / 前へ |
| カーソル下の単語を検索 | `*` |
| ハイライト消去 | `Esc` |
| ファイル内一括置換 | `:%s/old/new/g`（確認しながらは `/gc`） |
| 選択範囲だけ置換 | Visual 選択 → `:s/old/new/g` |

## VS Code 相当のパネル機能

| VS Code | キー | 備考 |
| --- | --- | --- |
| Explorer | `Space e` | ツリー内: `a` 新規作成, `d` 削除, `r` リネーム, `y` コピー。隠しファイルも表示（`Alt+h` で切替） |
| ファイル名で開く (Ctrl+P) | `Space Space` | `Enter` は現在ペインに開く。`Ctrl+v` 左右分割 / `Ctrl+s` 上下分割で開く |
| 開いているファイル一覧（「開いているエディタ」相当） | `Space ,` | このセッションで開いたバッファを最近使った順に表示。未保存は `+` マーク。`Enter` で切替 |
| 横断検索 (Search) | `Space /` | ripgrep 使用。結果は `Ctrl+j/k` で選択 → `Enter`（`Ctrl+v/s` も可） |
| 横断置換 | `Space s r` | grug-far。編集して保存すると一括適用 |
| 最近開いたファイル | `Space f r` | |
| ファイルパスをコピー (Copy Path) | `Space f y`（相対）/ `Space f Y`（絶対） | ホストのクリップボードにも届く（OSC 52） |
| Problems（診断一覧） | `Space x x` | Trouble。**現在ファイルのみは `Space x X`**。パネルを開いたまま `]q` / `[q` で**ファイルをまたいで**次 / 前のエラーへジャンプできる |
| **プロジェクト全体の型チェック** | `Space x c`（`:Typecheck`） | `tsc --noEmit` を全ファイルに実行し quickfix に一覧表示。`Enter` でジャンプ、`]q` / `[q` で巡回 |
| Outline（シンボル） | `Space c s` | |
| 統合ターミナル | `Ctrl+/` | 同じキーで閉じる |
| キーマップ検索 | `Space s k` | 「あのキー何だっけ」はこれ |
| コマンド一覧 | `Space s C` | |

**診断（エラー一覧）の範囲に注意**: `Space x x` などの LSP 診断は**このセッションで開いたことの
あるファイルの分しか表示されない**（VS Code の Problems と違い、未オープンのファイルは検査されない）。
プロジェクト全体を漏れなく洗うときは `Space x c`（型チェック → quickfix）を使う。

**ピッカー共通のプレビュー操作**（`Space Space` / `Space /` / `gr` など snacks ピッカー全般）:
プレビューだけ流し読みするなら一覧にいたまま `Ctrl+f` / `Ctrl+b` で下 / 上にスクロール。
本格的に読みたいときは `Alt+w` でフォーカスが「入力欄 → 一覧 → プレビュー」の順に巡回するので、
プレビュー内に入れば通常のカーソル移動（`j/k`・`Ctrl+d/u`・`/` 検索）がそのまま使える。
戻るのも `Alt+w`。`Alt+p` でプレビュー表示自体の ON/OFF、`Alt+m` でピッカーの最大化を切り替えられる。

## コード操作（LSP: vtsls / tailwindcss）

| 操作 | キー |
| --- | --- |
| 定義へジャンプ | `gd`（戻るのは `Ctrl+o`） |
| **定義を隣のペインで開く**（VS Code の「横に定義を開く」） | `gV` — 隣の通常ペインを再利用（なければ左右分割を作成）。元のペインは呼び出し元に残ったまま |
| 参照一覧（カーソル位置のシンボル） | `gr` — 横のプレビューは `Ctrl+f/b` でスクロール、`Alt+w` で中に入れる |
| このファイルの参照元一覧 (File References) | `gR` — 結果は下部パネル。**閉じるのは `Ctrl+j` で入って `q`** |
| 同じシンボルの次 / 前の出現へジャンプ（ファイル内） | `]]` / `[[`（`Alt+n` / `Alt+p` も同じ） |
| 同一シンボルのハイライト | 自動（カーソルを乗せて一拍待つ）。代入箇所だけ青系で区別される |
| 型情報・ドキュメント表示 | `K`（2回押すとフロート内に入る。**抜けるのは `q`**） |
| リネーム（プロジェクト全体） | `Space c r` |
| コードアクション（import 追加等） | `Space c a` |
| カーソル行のエラー全文を表示（波線の内容確認） | `Space c d`（2回押すとフロート内に入れる） |
| 次 / 前の診断へ（ファイル内） | `]d` / `[d`（エラーのみは `]e` / `[e`）。ファイル横断は Trouble（`Space x x`）+ `]q` / `[q` |
| 補完 | Insert モードで自動表示 → `Tab` で候補にフォーカス → `j` / `k` で上下移動 → `Tab`（または `Enter`）で確定。**未選択の間は j / k / Enter は通常の入力**（`↑` / `↓`、`C-n` / `C-p` でも移動可、`C-e` でキャンセル） |
| インレイヒント（引数名・推論型の薄い表示）の ON/OFF | `Space u h`（既定 OFF。見たいときだけ ON） |

**保存時整形**: 保存すると `node_modules/.bin/oxfmt` が自動実行される（`pnpm format` と同一結果）。
対象は ts / tsx / js / jsx / json。スニペット定義など `app/` の外の JSON も保存時に整形される。

**インレイヒント**: 引数の中の `selectors:` や行末の `: string` のような薄い表示はエディタが
重ねて描画しているヒントで、**ソースコードには含まれない**（ヤンクしてもコピーされない）。
本環境では**既定 OFF**（`lua/plugins/lsp.lua`）。`Space u h` で一時的に表示でき、
長い型は TS server が `...` に切り詰めるため、完全な型は `K`（ホバー）で確認する。

## ユーザースニペット（自作の定型文を補完に追加）

`.devcontainer/nvim/snippets/{filetype}.json` に **VS Code のユーザースニペットと同じ書式**で置く
（`~/.config/nvim/snippets` が symlink 経由でこのディレクトリを指している）。
ファイル名 = 対象 filetype: `typescript.json` / `typescriptreact.json`(.tsx) /
`javascript.json` / `markdown.json` / `lua.json` など。全 filetype 共通は `all.json`。
今開いているファイルの filetype は `:set filetype?` で確認できる。
`typescript.json` のスニペットは **`.tsx` でも候補に出る**よう設定済み（`lua/plugins/cmp.lua`）。
.ts / .tsx 両方で使うものは `typescript.json` に、JSX を含む .tsx 専用だけ
`typescriptreact.json` に書き分ける。

```json
{
  "Vitest describe block": {
    "prefix": "desc",
    "body": ["describe(\"${1:対象}\", () => {", "\t$0", "});"],
    "description": "補完メニューに出る説明文"
  }
}
```

- `$1` `$2` … がプレースホルダ、`${1:初期値}` で初期値付き、`$0` が最後のカーソル位置
- 使い方: Insert モードで prefix（例 `desc`）を入力 → `Tab` で候補にフォーカスし
  もう一度 `Tab`（または `Enter`）で展開 → `Tab` / `Shift+Tab` でプレースホルダ間を移動
- **VS Code と違い `//` コメントは書けない**（厳密な JSON のみ。1つでも書くとそのファイル全体が
  読み込み失敗になる）。書き方の説明は `typescriptreact.json` 先頭の `snippet-help` エントリ参照
- JSON を編集・追加したら **nvim を再起動**すると反映される（起動時に一度だけ読み込むため）
- コミュニティ製スニペット集（friendly-snippets）も同時に有効。`log` → `console.log()` など

## Git

| 操作 | キー |
| --- | --- |
| **lazygit を開く**（stage / commit / push / ブランチ / 差分閲覧の TUI） | `Space g g` |
| 次 / 前の変更ハンクへ | `]h` / `[h` |
| ハンクの差分をその場でプレビュー | `Space g h p` |
| 現在ファイルの差分を左右分割で表示（VS Code の差分ビュー相当） | `Space g h d` |
| 変更ハンク一覧から選んでジャンプ | `Space g d` |
| 変更ファイル一覧（git status） | `Space g s` |
| ハンクを stage / 取り消し | `Space g h s` / `Space g h r` |
| stage の取り消し | `Space g h u` |
| 行 blame 表示 | `Space g b` |

複数ファイルの差分をまとめて眺める・コミットを作る作業は lazygit（`Space g g`）が最適。
ファイル一覧で `Enter` → ハンク単位の差分、`Space` で stage、`c` でコミット、`P` で push、`q` で閉じる。

## Markdown

| 操作 | キー |
| --- | --- |
| 整形表示（ターミナル内プレビュー）の ON/OFF | `Space u m` |
| ブラウザでライブプレビュー | `Space c p`（※コンテナ内からはポート転送がないため既定では開けない） |

markdown ファイルを開くと render-markdown による整形表示（見出し・表・コードブロックの装飾）が既定で有効。素のテキストを見たいときに `Space u m` で切り替える。Markdown 用 LSP（marksman）もattach し、`gd` でリンク先ジャンプ、`gr` で参照箇所一覧が使える。

英語スペルチェックは無効化済み（日本語文書では全文が赤下波線になるため）。英文を書くときは
`:setlocal spell` で一時有効化できる（`]s` で次のミスへ、`z=` で修正候補）。

| **直前に表示していたファイルと交互にトグル** | `` Space ` ``（バッククォート）または `Ctrl+6` |
| バッファ一覧から選ぶ | `Space ,`（一覧中 `Ctrl+x` で選択中のファイルを閉じられる。連続実行可） |
| ファイルを閉じる（ペインは残る） | `Space b d`（未保存なら保存確認が出る） |

| ファイルとペインを両方閉じる | `Space b D` |
| 画面を上下 / 左右に分割 | `Space -` / `Space \|` |
| 分割間の移動 | `Ctrl+h/j/k/l` |
| 分割を閉じる | `Ctrl+w q` |

| **現在のペインを拡大 ⇔ 均等に戻す** | `Space m`（拡大比率は `keymaps.lua` 冒頭の `expand_width_ratio` / `expand_height_ratio` で調整） |

ペインを閉じるだけでファイルは開いたまま残り、`Space b d` はその逆。VS Code の
「タブを閉じる」に相当するのは `Space b d` の方。

## Claude Code 連携（claudecode.nvim）

| 操作 | キー |
| --- | --- |
| Claude Code ターミナルの表示 ⇔ 非表示 | `Space a c` |
| 前回のセッションを再開して開く | `Space a r` |
| **選択範囲を Claude に送る** | Visual 選択 → `Space a s` |
| 現在のファイルをコンテキストに追加 | `Space a b` |
| Claude の変更提案（diff）を適用 / 拒否 | `Space a a` / `Space a d` |
| Claude ウィンドウへフォーカス移動 | `Space a f` |
| Claude ペインの幅調整 | 境界線をマウスドラッグ、またはコード側ペインから `Ctrl+←/→` |
| **過去の会話を遡って読む** | `Ctrl+o`（Claude のトランスクリプトビューア。`j/k` スクロール・`/` 検索・`q` で閉じる） |
| Claude ペイン内で Normal モードに戻る | `F2`（見えている画面のヤンクやペイン移動に。`i` で入力に復帰） |

VS Code 拡張と同じ IDE プロトコルで接続され、nvim 内の Claude は「今開いているファイル・
選択範囲・LSP 診断」を自動で参照できる。変更提案は nvim の diff ビューで確認してから適用する。
Claude ペイン内ではキー入力が Claude 側に渡るため（ターミナルモード）、nvim の操作は
コード側ペインかマウスで行う。調整した幅はフォーカス移動後も維持される。

**過去の会話が nvim のスクロールで遡れないのは仕様**: Claude Code はフルスクリーン描画
（vim と同じ alternate screen 方式）のため、履歴はスクロールバックに流れない。会話を読むのは
`Ctrl+o` のトランスクリプトビューアが正式ルート（`[` を押すとスクロールバックへ全文書き出しも可能）。
どうしても nvim 側のスクロールで読みたい場合は Claude 内で `/tui default` を実行すると
従来レンダラー（履歴がスクロールバックに残る方式）へ切り替えられる（描画のちらつきは増える）。

## この環境固有の事情

- **文字サイズ**: ターミナル上で動くため nvim 側にフォント設定はなく、**Windows Terminal 側で変える**。
  一時的には `Ctrl+-` / `Ctrl++`（`Ctrl+0` でリセット、`Ctrl+マウスホイール` も可）。
  恒久的には `Ctrl+,` → 使用中のプロファイル → 外観 → フォントサイズ（既定 12）。
  変更すると nvim / tmux は新しい行数・列数へ自動追従する
- **クリップボード**: ヤンク（`y`）は OSC 52 で Windows 側クリップボードへ届く。
  逆方向（ホスト → nvim）はターミナルのペースト `Ctrl+Shift+V` を Insert モードで使う
- **プラグイン管理**: `:Lazy`（更新は `:Lazy sync`。`lazy-lock.json` が変わるので git 管理）
- **LSP 管理**: `:Mason`（サーバーの追加・更新） / `:LspInfo`（attach 状況確認）
- **健康診断**: 動作がおかしいときは `:checkhealth`
- **コンテナ再ビルド後**: 初回起動でプラグイン・LSP が自動再取得される（数分）。
  先に済ませたい場合は `.devcontainer/README.md` の「Neovim を使う」参照
